# Workspace v2 — 2026-10-17

The product now opens real, persistent business workspaces. Demo is an explicitly separate path. Local email/password accounts remove the Supabase setup dependency for everyday local use; Supabase remains optional. Passwords use salted PBKDF2-SHA256 with 600,000 iterations and constant-time verification. Persistent accounts use the same tenant-scoped HttpOnly sessions as before. `database/migrations/002_local_accounts.sql` creates the local users table; runtime `create_all` also adds it idempotently.

Sales entry records historical selling and cost prices and atomically decrements stock using a conditional SQL UPDATE. An insufficient balance rejects the sale without adding a record. Receiving adds stock without treating the stock asset as an operating expense. Expense entry affects net profit; deleted expenses leave an audit record. Historical CSV/XLSX imports append financial history without changing the current physical stock.

The decision center derives replenishment recommendations from the greater of the configured reorder point and three days of observed daily demand. The three-day lead time is an assumption, not an imported supplier promise. Order budget = suggested units × current purchase cost, summed with Decimal. Price-at-or-below-cost alerts detect zero or negative unit margin. Break-even revenue = total recorded operating expenses / historical gross margin fraction for the available dataset; it is unavailable without positive margin and operating expenses, and is not a forecast.

OpenAI Responses receives calculated metrics, product/stock actions, business identity and recent tenant-scoped conversation. The app keeps numeric financial answers deterministic and asks the model for a qualitative action plan. Numeric model output is rejected instead of replacing authoritative calculations. The response is labeled OpenAI only after successful provider output; provider key/quota/network errors are shown explicitly. Conversation records persist in `records` with kind `conversation`. Status responses expose configuration/model/error codes but never the key.

Visual redesign uses locally bundled Onest (including Cyrillic extended) and Manrope, larger type, teal accents, clearer cards and forms, and a dashboard organized around facts, problems and actions. Dark and light themes are retained. Cashier, pricing and inventory simulators remain available.

Verification: 35 backend tests cover the original calculations plus real-account persistence, password hashing, sales/stock consistency, receipt resolution, break-even arithmetic, expenses and tenant-scoped history. Browser workflows cover real registration, product entry, sale, expense, receipt, logout/login persistence and mobile layout, alongside the original demo, import, simulator, vision and report scenarios. Hardware webcam access still needs a manual check. Live OpenAI verification returned `401 invalid_api_key` for the supplied key; this is a provider credential blocker, not a successful AI connection.
